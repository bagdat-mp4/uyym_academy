# Проверка MVP учебного контента

Дата: 11 октября 2026. Среда: Windows, Node.js 22.22.0. Это проверка исходного кода и локальных панелей управления; живые Supabase/Google Drive владельца не подключены. Сайт не опубликован, платные услуги не активированы.

## Автоматические результаты

`npm test`: **56 тестов, 55 PASS, 0 FAIL, 1 SKIP**. `npm run build`: TypeScript без ошибок, Vite production bundle создан. `npm ci` сообщил 0 известных advisories; это не гарантия отсутствия неизвестных уязвимостей.

| Проверки | Результат | Что подтверждено |
| --- | --- | --- |
| SQL этапа 1 | 12 PASS | FORCE RLS, отсутствие browser grants/RPC, private Storage policies, единственные binding/session, epoch, append-only журнал, backend role |
| SQL управления | 10 PASS + 1 SKIP | Пять последовательных миграций, резервирование мест, перенос/понижение вместимости, revisions, immutable оплаты/корректировки/квитанции, безопасный Auth journal, ограниченная очистка с FK |
| API авторизации и аккаунтов | 20 PASS | Fastify + SQL + настоящие P-256 подписи, TOTP, чужая cookie/ключ, replay/CSRF, второй браузер без вытеснения, замена, блокировка/сброс, idempotency, безопасное продолжение создания и частичные Auth-сбои |
| API управления | 8 PASS | ADMIN-only списки, объектные права TEACHER, отзыв can_manage_access до изменения/повтора, независимые курсы, вместимость, настройки, ручные оплаты, история исправлений и именованные объекты журнала |

| Криптография и границы | 4 PASS | Неэкспортируемый Web Crypto ключ, контекст подписи, RFC6238/replay, AES-GCM, E.164, интервалы и размер media части |

SQL выполняется на настоящем embedded PostgreSQL PGlite. Системные Auth/Storage сущности и роли минимально созданы тестовой fixture, поэтому это не приёмка живых настроек Supabase. API вызываются через `app.inject`, выполняют реальные маршруты и SQL; удалённые ответы Supabase Auth **явно симулируются**. Успешное получение бинарного видео из Drive не симулируется и не заявляется проверенным.

Auth regression cases: потеря ответа создания завершается по заранее известному UUID без дубликата; временный пароль не повторяется и не сохраняется в journal. Сброс отзывает сессии/тикеты/grants, сохраняет ключ и закрывает вход до завершения. Проверены недоступность до удалённого изменения, потеря ответа после него, явный повтор после периода ожидания и отказ устаревшего marker снять новую блокировку. Это не доказывает отсутствие крайне позднего commit удалённого сервиса; ограничение описано в `management-guide.md`.

Реальный конкурентный тест двух PostgreSQL connections имеет явный SKIP без `TEST_DATABASE_URL`. PGlite serial transport не доказывает отсутствие многопоточных гонок или deadlocks. Порядок блокировок согласован в управлении/CLI/security/cleanup; для вместимости требуется READ COMMITTED, и иной режим отклоняется SQL-функцией. Для живой проверки используйте отдельную тестовую базу, не production.

## Проверка через интерфейс

На `http://localhost:5174/#account` использовалась изолированная `tests/ui-fixture.ts`: настоящие BFF-маршруты, PostgreSQL и IndexedDB/Web Crypto, временная база, явно тестовый Auth-провайдер. Никакие аккаунты владельца или внешние сервисы не изменялись.

Через интерфейс выполнены вход владельца с TOTP, создание преподавателя и ученика, создание курса и группы, назначение преподавателя с отдельным разрешением, выдача доступа с датами, изменение срока и отзыв. Для текущего этапа дополнительно открыты ADMIN → «Учебный контент» → Calculus I → «Домашние задания», список работ назначенной группы и неизменяемая версия ответа синтетического ученика. Статус изменён на «Проверено», сохранены оценка 18/20 и комментарий; интерфейс показал подтверждение и обновлённый статус из временной PostgreSQL. Форма использует имена/названия, UUID вводить не требуется. На мобильном viewport окно проверки перестраивается в одну колонку, а `document.scrollWidth` совпал с `window.innerWidth`; временный размер возвращён к обычному после проверки. Это Chromium-предпросмотр, не физический Android/iPhone.

Публичная главная KZ/RU, форма входа, курсовое окно и состояния отсутствующих контактов проверены на этапе 1. Преподаватели и контактные данные не выдуманы; синтетические имена этой проверки существуют только во временной тестовой базе. Screenshot проверки управления сохранён отдельно в outputs.

В production smoke check этапа 1 `/`, JS и `/brand.png` возвращали 200, `/.env` — 404, приватный API без конфигурации — 503; `/api/health` честно показывал отсутствие подключений. Эти проверки не подтверждают внешние сервисы. Защищённые ответы имеют `no-store`, клиент не содержит Supabase service key, Google credentials или server tokens. Учебный контент и workflow ответов добавлены отдельными миграциями `005` и `006`; прежние миграции не переписаны.

## Незавершённая внешняя приёмка

- Живые Supabase Auth/Admin REST, запрет signup, Data API/RPC/Storage, фактические права `uyym_backend`.
- Настоящий PostgreSQL с двумя connections, нагрузка и возможные гонки управления/очистки/отзыва.
- Restricted Drive ACL и sharing backend identity, `files.get?alt=media` 206, поток, quotas и фактический трафик.
- FFmpeg реальной записи, init/fMP4 codec, успешное воспроизведение, перемотка и отзыв во время просмотра.
- Chrome/Edge на ноутбуке, Android и Safari на физическом iPhone, persistence ключа, очистка/перезапуск/смена сети.
- HTTPS deployment, домен, пробный backup/restore и восстановление Auth идентичностей.

Плеер использует подписанный JS fetch + MSE, ограниченные части до 1 MiB и будущий буфер до 30 секунд. Ветка Safari ManagedMediaSource основана на [документации WebKit](https://webkit.org/blog/14735/webkit-features-in-safari-17-1/), но не проверена на реальном iPhone. Это не DRM; уже полученные байты и запись экрана отозвать нельзя.

Текущий MVP реализует опубликованные задания, приватные вложения, версии ответов, оценку/комментарий, персональное разрешение поздней сдачи, объявления, посещаемость, явное завершение урока, сохранение позиции просмотра и архив Quiz/Midterm/Endterm/Final. Автоматическая загрузка файлов в Drive остаётся отдельным этапом. Manifest связывается с сегментами пакетом по уникальным именам файлов в разрешённой папке; сами файлы оператор всё ещё загружает в Drive. Реальную video-приёмку продолжайте по `poc-acceptance.md`, не отмечая её выполненной по локальному UI.
