## Открытые инциденты

**PP1 STUDENT:** исторически подтверждённый HTTP 500 / `42P18` вызван лишним неиспользуемым `$2` при `group_id=NULL`; STUDENT progress сдвигался на `$3`, а PostgreSQL не мог вывести тип пропущенного параметра. `2d6b2db` убирает лишний bind; локальные API-тесты покрывают собственный progress/submission и изоляцию групп. Исправление уже в main; здесь оно не дублируется. Текущий статус/срок/group_id реального зачисления и новый HTTP status production content — **BLOCKED** без одобренной STUDENT-сессии/безопасной диагностики. Успех ADMIN таким доказательством не считается.

**Первый кадр/heartbeat 403:** текущая production-причина **BLOCKED**: нет Response `code`, свежих измерений и серверных фаз для того же PP1-видео. Сам по себе 403 не доказывает причину; timeout/grant/proof правила не расширялись и не обходились. Родительский `f056a92` сохраняет проверки Drive перед каждой частью, повторную проверку grant/доступа после upstream headers, и не регистрирует progress PATCH для ADMIN/TEACHER.

Безопасный следующий шаг владельца в уже одобренном STUDENT-браузере: открыть тот же урок; записать HTTP-статусы и числовые времена playback, первых media part=-1/0, время до первого кадра; при heartbeat 403 сообщить только `code` из Response. Не присылать Headers/HAR/cookies/полные media URL. Для real before/after нужны одно видео, один браузер/сеть, отдельно холодный старт Render и медианы трёх тёплых запусков. Свежие серверные фазы — через предусмотренную opt-in диагностику, без смены настроек в этой задаче.

## Безопасность и выпуск

Новых HTML sinks, пользовательского `dangerouslySetInnerHTML`, клиентских серверных ключей, API-обходов, ослаблений ADMIN/TEACHER/STUDENT, device proof, enrollment, grant и Drive permissions не добавлено. Роли в AccountLink — только подписи навигации. Backend безопасности в коммите аудита не меняется. Существующие регрессии изоляции курсов/групп/личных результатов, ролей, proof и отзыва grant прошли. XSS-риск новых изменений оценён чтением кода: новый UI выводит строки через React. Это не заявление о полном XSS-аудите или пентесте.

После ревью и отдельного разрешения на публикацию безопасный порядок относительно проверенного `origin/main=761efc6`: `f056a92` → коммит текущего аудита. `2d6b2db` повторно не переносить, `5c40111` целиком не cherry-pick. Перед выпуском заново проверить ancestry на актуальном main и выполнить real PP1-проверку выше. Все production-действия, необходимые разрешения и проверка реального STUDENT остаются отдельным этапом.

Полные локальные артефакты находятся в игнорируемом `work/vercel-audit/`: bundle-before/after, player-language-before/after, browser-checks.json, player-layout.json, числовые BFF metrics, логи тестов/сборки и снимки. Секреты, пользовательские local media и fixture-данные в deployment не добавляются.
