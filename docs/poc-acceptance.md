# POC: протокол проверки приватного видео и браузера

Статус на 10 октября 2026 года: **внешний POC НЕ ВЫПОЛНЕН**. Владелец сообщил, что Supabase и выделенной папки Drive с тестовым MP4 пока нет; заказаны код и инструкции подключения. Этот файл содержит воспроизводимые критерии приёмки. Наличие красивого интерфейса, успешный build и локальные unit tests не считаются результатом реального POC.

Не создавайте заполненные PASS записи без фактического выполнения. Результаты локальных проверок исходного кода фиксируются отдельно в отчёте поставки. После подключения запишите commit, версии браузеров, OS, дату, тестовый hostname и обезличенные ID. Не помещайте в отчёт passwords, cookies, recovery codes, bearer tokens, приватные ключи или исходные Drive URL.

## Предусловия

1. Отдельный тестовый Supabase с применёнными SQL миграциями и отключённой самостоятельной регистрацией. Проверены запреты `anon`/`authenticated` для private tables, RPC и Storage.
2. Один реальный приватный MP4 владельца в разрешённой папке Drive; backend identity имеет чтение, ученик не имеет permission. MIME, ACL, родители, размер и кодеки проверены. Не используйте публичный sample URL как доказательство приватного Drive.
3. HTTPS на реальном hostname, Secure/HttpOnly/SameSite cookies. `localhost` допустим для разработки, но Android/iPhone должны тестировать HTTPS endpoint.
4. Bootstrap выполнен локально владельцем; для ADMIN настроен TOTP, recovery codes сохранены вне репозитория. Созданы два STUDENT, два курса/группы, два TEACHER с разными назначениями. Реальные люди не нужны — тестовые аккаунты создаёт владелец.
5. Ученик получил индивидуальный временный пароль и сменил его. Пароль существует только в Supabase Auth; старый пароль администрация не может прочитать.
6. Браузерный ECDSA P-256 private key с `extractable=false` хранится как CryptoKey в IndexedDB. Успешный export private key должен быть невозможен. Проверены перезапуск и persistence. При невозможности сохранить/использовать CryptoKey учебный доступ закрывается с объяснением; защита не отключается.

| 1 | Войти в браузере A правильным телефоном/паролем | До одобрения доступны настройка/статус заявки; lesson, materials и media закрыты | НЕ ВЫПОЛНЕНО |
| 2 | Владелец лично проверяет ученика и одобряет конкретный fingerprint публичного ключа | Одна активная привязка; audit event с actor/target, без секретов | НЕ ВЫПОЛНЕНО |
| 3 | Войти A после одобрения и открыть опубликованный урок действующего курса | Видео поступает через BFF; клиент не получает Google file ID/media URL/token | НЕ ВЫПОЛНЕНО |
| 4 | Воспроизвести, перемотать вперёд/назад, изменить скорость, звук и fullscreen | Ограниченные подписанные части; новые части выдаются после проверки proof/session/enrollment | НЕ ВЫПОЛНЕНО |
| 5 | Войти в другом браузере B с тем же правильным паролем | B не получает учебных данных. A продолжает работать, старая session не вытесняется | НЕ ВЫПОЛНЕНО |
| 6 | Во время воспроизведения в A приостановить зачисление | Следующая новая часть отклонена; уже полученный буфер может доиграть в установленных пределах | НЕ ВЫПОЛНЕНО |
| 7 | Возобновить зачисление и выполнить разрешённую замену на B | Атомарно отозваны старый key/session/grants, повышен auth_epoch, активирован B | НЕ ВЫПОЛНЕНО |
| 8 | Повторить запрос A после замены | A не получает новые данные даже со старыми cookies/proofs/grants | НЕ ВЫПОЛНЕНО |

При отказе другого браузера показывается: «Бұл аккаунт басқа құрылғыға тіркелген. Құрылғыны ауыстыру үшін әкімшіге хабарласыңыз».

## Критические API проверки

Все строки ниже пока **НЕ ВЫПОЛНЕНЫ на реальных внешних API**. Тестировать серверные HTTP ответы и состояние БД, а не только скрытие кнопок.

| Проверка | Ожидаемое доказательство |
| --- | --- |
| Чужая попытка с правильным паролем | Device request/status разрешён, учебный API отклонён; действующая session A не отозвана |
| Logout и истечение session | Cookie/session перестают действовать, approved key остаётся привязанным; пароль не регистрирует B |
| Смена/сброс пароля | Старый пароль отклонён, browser binding сохраняется; B по новому паролю не получает урок |
| Очистка IndexedDB и всех browser data | Новый ключ требует заявки/одобрения владельца; автоматической повторной регистрации нет |
| Смена IP/Wi-Fi, несколько вкладок | Законный ключ работает; tabs используют одну application session, IP не является условием привязки |
| Копия cookie A в B | Без подписи A доступ отклонён; cookie не является единственным доказательством |
| Replay challenge | Первый корректный proof принимается, второй с тем же nonce отклонён, включая одновременную отправку |
| Перенос proof | Изменение session_id, method, path, purpose, timestamp или запроса отклонено; нельзя подписать одно действие и выполнить другое |
| Истёкший/будущий proof | TTL и допустимое clock skew применяются сервером |
| Параллельное одобрение двух заявок | После двух конкурентных запросов БД содержит не больше одного approved binding; уникальное ограничение и транзакция работают |
| Параллельный login A | Не создаются две active application sessions; несколько вкладок могут пользоваться одной session |
| Renew session из B | Перехваченный refresh/application cookie без одобренного ключа не продлевается |
| Прямой Supabase login | Полученный raw JWT не читает private таблицы, Storage, RPC и BFF учебные endpoints |
| Публичная регистрация Supabase | Signup отклонён; admin provisioning работает только server-side |
| Чужой lesson/material/submission ID | Нет IDOR; STUDENT не читает другой курс/ученика, TEACHER не читает/изменяет чужую группу |
| Неактивное/будущее/истёкшее зачисление | Запрос отклонён по серверному UTC времени; действующий другой предмет остаётся доступен |
| Непубликованный урок или решение до открытия | Данные отклонены API независимо от старой страницы/модификации frontend |
| Google исходник напрямую | Без владельца/backend identity файл закрыт; STUDENT Google account не получил Drive permission |
| Публичный ACL или чужая папка | Публикация/новая выдача отклонены; нет «fallback сделать публичным» |
| Огромный/несколько Range, пустой диапазон, вне файла | Запрос отклонён либо ограничен явным серверным правилом; нельзя одним ответом получить весь многочасовой файл |
| Playback grant в B | Один grant не открывает media: требуются та же session, approved key, одноразовый proof и актуальный доступ |
| Блокировка/замена во время media | Новые части немедленно не выдаются после commit. In-flight/уже буферизованные bytes имеют измеренную верхнюю границу |
| Ошибка Drive 403/429/5xx | Воспроизведение сообщает ошибку/ограниченный retry; credentials не раскрываются, публичная ссылка не появляется |
| CSRF и Origin | Изменяющий запрос без CSRF token/неверной origin отклонён; cookie flags проверены DevTools |
| Попытки входа | Rate limiting действует, сообщения не перечисляют существующие телефоны |
| Учитель без делегированного access permission | Даже в своей группе не изменяет зачисление; с разрешением меняет только существующий свой roster; роли/устройства закрыты |
| Задания, versions и grades | После refresh и повторного login сохраняются ответ, вложения, версия/дата, оценка/комментарий; другой STUDENT их не читает |
| Дедлайн и файлы | До дедлайна обновление версии разрешено, после — только с разрешением; ≤2 файла, каждый ≤5 MB, сервер проверяет тип/размер; CPP читается как текст |
| TOTP и recovery | ADMIN без второго фактора не выполняет привилегированные действия; одноразовый recovery code повторно отклонён, журнал содержит восстановление без кода |
| Секреты | В `dist`, Git истории, публичном API и логах нет service_role, DB password, Google credentials/token, существующих паролей |

## Проверка плеера на устройствах

Каждая платформа проверяется отдельно. Эмуляция mobile viewport на ноутбуке не является проверкой Android/iPhone. Установите версии и зафиксируйте API поддержки на том устройстве; наличие `MediaSource`/`ManagedMediaSource` и нужного H.264/AAC container/codec не означает автоматически успешное playback.

| Платформа | Реальное видео + approval | Seek + fullscreen | Persistence после перезапуска | Отказ B + отзыв во время просмотра |
| --- | --- | --- | --- | --- |
| Chrome на ноутбуке | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО |
| Edge на ноутбуке | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО |
| Chrome на Android | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО |
| Safari на iPhone | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО | НЕ ВЫПОЛНЕНО |

Видео не загружается целиком в Blob перед просмотром. Нативный `<video src>` не умеет произвольные JS proof headers: проверьте, что выбранный транспорт действительно делает `fetch` каждой части с proof и передаёт её поддерживаемому Media Source. Каждый chunk соответствует поддерживаемому контейнеру; произвольный кусок обычного MP4 не является сам по себе fMP4 сегментом. Если браузер/codec не поддержан, показывается понятное состояние и доступ не переводится на незащищённую ссылку.

Измерьте maximum buffer ahead, размер/длительность одной части, количество одновременных частей и задержку до отказа после commit блокировки. Слишком далёкое автоматическое предварительное чтение — дефект. Для длинного урока memory не растёт пропорционально полному файлу. Повторите с медленной сетью, transient disconnect и сменой Wi-Fi.

## Фиксация результата и граница защиты

Для каждого выполненного пункта сохраняйте: дата/commit, окружение, обезличенные входные условия, HTTP status, ожидаемое/фактическое состояние БД, размер буфера/задержку, PASS/FAIL и обнаруженные отклонения. HAR очищается от cookies, authorization/proof headers, PII и Google source identifiers до включения в отчёт.

POC считается успешным только после реального закрытого Drive потока, перемотки, отказа B без вытеснения A, отзыва/замены и обязательных API проверок на целевых браузерах. До этого дальнейшие продуктовые экраны могут быть подготовлены, но эксплуатационная готовность остаётся неподтверждённой. Нет искусственного лимита 30 аккаунтов: 30 — стартовое допущение нагрузочного расчёта.

Проверяется одобренный браузерный профиль, а не физический компьютер с абсолютной точностью. Не обещаются MAC/IMEI/серийный номер, DRM, отзыв уже скачанных материалов или защита от записи экрана, удалённого управления и специально модифицированного клиента. Watermark имени/маскированного телефона и удаление кнопки скачивания уменьшают обычное распространение, но не отменяют эти ограничения.
