# UYYM Academy — управление академией и технический POC

Репозиторий содержит публичный сайт, кабинеты трёх ролей, SQL-миграции, защищённый учебный контент и POC авторизации браузера/приватного видео. **Это ещё не подтверждённый production-запуск.** Supabase и реальный Google Drive владельца пока не подключены. В текущем MVP ученик смотрит опубликованные уроки и закрытые материалы, сдаёт домашние работы версиями, получает оценку/комментарий, читает объявления и видит сохранённый прогресс. Преподаватель ведёт посещаемость только своей группы.

## Что сделано

- React + TypeScript + Vite + Tailwind: KZ по умолчанию, RU, адаптивная главная, курсы, формат, FAQ, контакты без выдуманных людей/номеров.
- Node 22 / Fastify BFF: Supabase Auth телефон + пароль через сервер, временный пароль, E.164, HttpOnly cookies, CSRF, ограничения попыток, серверный TOTP владельца.
- Web Crypto ECDSA P-256: неэкспортируемый приватный CryptoKey в IndexedDB, заявки на браузер с ручным одобрением, одноразовые подписанные challenges, привязка метода/пути/тела/сессии/nonce/epoch.
- PostgreSQL: закрытая схема, FORCE RLS, запрет браузерного JWT на таблицы/RPC/Storage, единственная активная привязка и application session, атомарный отзыв устройства и grants, журнал.
- Плеер через подписанный JS fetch и MSE: init + короткие fMP4 части до 1 MiB, перемотка по временному индексу, heartbeat, до 30 секунд будущего буфера, имя и маскированный номер.
- Drive readonly identity: проверка папки, Restricted ACL, MIME и размера; ограниченный Range-поток. Google ID/credentials студенту не выдаются.
- ADMIN: пользователи, курсы, группы, назначения преподавателей, доступы, браузеры, учебный контент, публичные настройки и журнал; поиск, фильтры и пагинация. Платёжные таблицы и API сохранены, но повседневный раздел оплат скрыт на этом этапе.
- Учебный контент: черновики/публикация уроков, домашние задания с неизменяемыми версиями ответа и до 2×5 MB файлов ученика, проверка/оценка/комментарий и разрешение поздней сдачи; приватные материалы до 5×5 MB и архив Quiz/Midterm/Endterm/Final с фильтрами. Storage читается только backend после свежей проверки сессии, ключа и курса.
- Учебное взаимодействие: групповые объявления, расписание группы, посещаемость по конкретному уроку и сохранение позиции просмотра. Завершение урока ставится только явной кнопкой ученика.
- Пакетная регистрация Drive-видео: manifest хранит имена `init.mp4`/`part*.m4s`, backend находит их в одной Restricted-папке и проверяет ACL/MIME/размер; ручной ввод ID каждого сегмента не нужен.
- TEACHER: свои назначения и ученики своей группы; изменение существующего доступа только при отдельном `can_manage_access`, с повторной серверной проверкой.
- Управление: атомарная вместимость группы, даты UTC / отображение Asia/Almaty, optimistic revision, квитанции повторных запросов, безопасный журнал удалённых Auth-операций и явное восстановление после частичного сбоя.
- CLI: защищённый bootstrap/recovery владельца, обслуживание временных данных, подготовка и регистрация видео. Создание пользователей и обычный сброс пароля выполняются через ADMIN-панель.

Домашняя работа проверяет дедлайн на сервере, сохраняет каждую отправку отдельной версией и показывает ученику только его результат. Преподаватель получает список и историю работ только назначенной группы.

## Быстрый локальный запуск

```powershell
npm ci
npm test
npm run build
npm run dev
```

Откройте `http://localhost:5173` (используйте именно localhost для совпадения Origin с `.env.example`). Без `.env` сайт показывает параметры из задания, а приватные API возвращают понятную ошибку 503. Фиктивного администратора/пароля и публичной регистрации нет.

После подключения сервисов скопируйте `.env.example` в `.env`, заполните только серверные значения. Не отправляйте `.env`, Google JSON, пароль БД, TOTP или recovery codes в чат/Git. `npm start` отдаёт собранный сайт на `127.0.0.1:8787`; для такого локального режима установите `APP_ORIGIN=http://localhost:8787`. В production нужны HTTPS и `COOKIE_SECURE=true`.

Для базы, уже обновлённой до домашних работ, примените `supabase/migrations/202610140007_engagement.sql`. Для новой базы примените все семь миграций по порядку, затем `supabase/backend-role.sql`, который создаёт роль и не предназначен для повторного запуска. Сначала сделайте резервную копию; подробности — в инструкции управления.

## Изолированная проверка интерфейса без внешних сервисов

В двух терминалах из корня репозитория:

```powershell
node --import tsx tests/ui-fixture.ts
npx vite --config tests/ui-vite.config.ts --host 127.0.0.1
```

Откройте `http://localhost:5174/#account`. Первый терминал выводит **синтетические тестовые** телефон, пароль и текущий TOTP. Здесь работают настоящие маршруты BFF, SQL и Web Crypto; только внешний Supabase Auth заменён тестовым провайдером, база временная и очищается при остановке процесса. Drive не симулируется. Этот режим расположен в `tests/`, не подключён к обычному серверу и не предназначен для эксплуатации. Он позволяет повторить сценарий создания преподавателя/ученика/группы и управления доступом без выдачи mock за живые сервисы.
